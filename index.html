Plan & elevator pitch · v0 · pre-implementation

One pipeline.
Any niche. Every short.

ReelForge ingests your raw footage or a pure text brief, researches what's trending, finds or generates the best moments, cuts them into caption-ready 9:16 Shorts & Reels, and pings you for a one-tap approval before anything goes live. Point it at bike POV clips today, kids' nursery rhymes tomorrow, TV-series hot takes next week — same engine, different config.

The idea

A content factory you configure, not rebuild

Every creator workflow is the same seven moves in a different costume. Instead of building a bike-video tool, then a kids'-rhyme tool, then a TV-recap tool, ReelForge treats niche as data. You write a ContentProfile; the engine swaps sources, research signals, editing looks, voices, and publishing targets accordingly.

🎯

Generic by design

Topic, channel, audience, captions, and color grade are all inputs. The same code path drives cycling edits and pastel lullabies.

🔀

Two creation modes

Footage mode mines your real clips for highlights. Generative mode builds video from scratch (script → voice → music → animation). Or blend both.

📈

Views & taste

Trend research plus a performance feedback loop chase reach — but a quality gate and your approval keep the output fun and on-brand, not spammy.

🧩

Pluggable everything

Each stage is an adapter behind a stable interface. Swap OpusClip for a local FFmpeg cutter, or Veo for Kling, without touching the orchestration.

🙋

You stay in control

Nothing publishes silently. A draft + preview link lands in Telegram/Slack/email; you approve, tweak, or reject before it's scheduled.

⚖️

Compliant by default

COPPA "made-for-kids" flags, AI-content disclosure, clean-licensed music, and per-platform rate limits are first-class config, not afterthoughts.

How it fits together

System architecture

A Python "product" core (the bespoke AI logic) wrapped by a durable orchestrator for scheduling, retries, and observability. A single ContentProfile flows through every stage and selects the adapters used at each step.

Stage by stage

The seven stages

Each stage is an independent, testable component with swappable adapters. Tags below show the leading pick and open-source alternatives.

01 INGEST

Pull new media from anywhere

Watch a source, sync new files, register them with metadata, dedupe by hash. Works for real footage and as the trigger for pure-generative runs.

  • Cloud + local connectors via one abstraction
  • Insta360 exports (reframed .mp4/.insv), Drive, S3
  • Proxy transcodes for fast analysis
rcloneFFmpegDrive/Dropbox API
02 RESEARCH

What's trending + idea generation

Blend trend signals across platforms, then have Claude rank angles for your niche/audience and draft hooks, titles, and descriptions.

  • YouTube trending + search velocity, Google Trends
  • TikTok Creative Center (cross-platform early signal)
  • vidIQ (has a Claude MCP connector) for niche outliers
vidIQ MCPGoogle TrendsClaude
03 UNDERSTAND

Find the interesting parts

Detect shot changes, transcribe speech, then use a vision/LLM pass to score each segment for interest, energy, safety, and b-roll usefulness.

  • Scene cuts: PySceneDetect (content + adaptive)
  • Transcript + word timings: Whisper
  • Multimodal scoring → ranked highlight list
PySceneDetectWhisperClaude vision
04 BUILD

Assemble the short

Footage mode cuts & auto-reframes highlights to 9:16 with subject tracking. Generative mode turns a script into voiced, scored, animated scenes. Then captions, color grade, and brand kit are layered on.

  • Reframe/subject-track → 9:16, hook-first ordering
  • Karaoke captions burned in; LUT color grade
  • Music bed + optional AI voiceover
FFmpeg/MoviePyOpusClip/VizardVeo/Kling
05 REVIEW

Notify + approve before posting

The default gate. You get a preview link, thumbnail options, and the caption/hashtags. One tap approves; you can request an edit or reject.

  • Telegram/Slack bot or email with preview
  • Approve · regenerate · edit copy · reject
  • Optional "auto-approve" per trusted profile
Telegram botSlacksigned preview URL
06 PUBLISH

Upload & schedule, rate-limit aware

Push to YouTube Shorts and Instagram Reels through official APIs, respecting per-platform quotas and posting at high-engagement times.

  • YouTube Data API v3 (videos.insert)
  • Instagram Graph API (container → publish)
  • Best-time scheduling + backoff on quota
YouTube APIIG Graph APIUpload-Post (multi)
07 LEARN

Feed performance back

Pull views/retention per post, attribute wins to hooks, formats, lengths, and colors, and let the next profile run bias toward what works.

  • Analytics pull per platform
  • Hook / format / length leaderboard
  • Auto-tune profile defaults & A/B thumbnails
YT Analytics APIIG InsightsDuckDB/SQLite
08 CROSS-CUT

State, secrets, cost, safety

A content ledger tracks every asset and job; a policy layer enforces disclosure, kids-safety, and licensing; a cost meter caps generative spend.

  • Job/asset state in SQLite→Postgres
  • Policy checks: COPPA, AI disclosure, music license
  • Per-run budget guardrails on paid APIs

The generic contract

One profile drives it all

This is the object the whole system reads. To launch a new channel or niche, you write one of these — no code changes. Everything you asked to control (topic, channel, audience, captions, color grade) is a field.

# profiles/bike_pov.yaml — a footage-mode profile
id: bike_pov
niche: "mountain & city cycling POV"
channel: { youtube: "@YourBikeCh", instagram: "yourbike.ig" }

audience:
  segment: enthusiast_hobbyist    # see Audience taxonomy
  age: "18-34"
  tone: high_energy

source:
  mode: footage               # footage | generative | hybrid
  connectors: [insta360_cloud, gdrive, local]

research:
  enabled: true
  signals: [youtube_trending, google_trends, tiktok_cc, instagram]

edit:
  aspect_ratio: "9:16"
  length_s: [15, 45]
  hook_first: true
  captions: { enabled: true, style: karaoke_bold, lang: en }
  color_grade: { lut: teal_orange_punch, look: vivid_action }
  music: { source: stable_audio, mood: energetic_electronic }
  voiceover: { enabled: false }

publish:
  platforms: [youtube_shorts, instagram_reels]
  schedule: best_time
  approval: required        # required | auto
  ai_disclosure: false
  made_for_kids: false

A generative kids profile flips source.mode: generative, points color_grade.lut at pastel_soft, sets made_for_kids: true, and swaps the build adapters — nothing else changes.

Same engine, three costumes

Worked examples

Proof the abstraction holds: three wildly different channels expressed purely as configuration.

Source → Story

Insta360 rides land in the cloud. ReelForge scene-detects each ride, scores segments for speed/near-misses/scenery, and picks 2–4 highlights per short. Research suggests hooks like "POV: the sketchiest line in [trail]".

Look & feel

Auto-reframe keeps the trail centered; teal-orange punch LUT; bold karaoke captions; licensed energetic bed from Stable Audio. No voiceover — the ride speaks.

Audience

Enthusiast hobbyists, 18–34, high-energy tone. Cross-posts to Shorts + Reels. Approval required while you build trust in the cuts.

Why it wins

Real, authentic POV + trend-aligned hooks + tight hook-first edits. Cheapest mode to run: mostly open-source, minimal paid generative spend.

Brief → Song → Scenes

No footage needed. Claude writes an original rhyme + scene list; music model produces the song; a kids-styled generator (Atlabs/Steve AI-class, or Kling/Veo for custom) animates consistent characters per scene.

Look & feel

Pastel-soft palette, 3D-cartoon or cozy-plush style, gentle pacing, sing-along captions synced to lyrics, warm friendly narration voice.

Audience & safety

Kids 0–5 + parents. made_for_kids: true (COPPA), AI-content disclosure on, human review mandatory — character warmth & safety still need your eyes.

Why it wins

Serialized characters + steady output = subscriptions. Fully generative means infinite catalog, but higher API cost and stricter review.

News → Take → Cutaways

Research pulls what's spiking about a show/episode. Claude drafts a spicy-but-fair take; TTS or your own voice narrates; b-roll is licensed stills/clips or AI-generated cutaways (no copyrighted frames).

Look & feel

Clean-bright or moody LUT to match the show's vibe; punchy captions; text-on-screen callouts; recognizable recurring intro sting.

Audience

Fandom / superfans, 18–40. Timing matters — publish within hours of episode drop. Hybrid: a little real (your voice) + generative b-roll.

Why it wins

Rides the episode-drop spike; opinion + community bait drives comments. Watch fair-use: commentary yes, re-uploading clips no.

Reality checks

Platform limits & compliance

These constraints shape throughput and must be designed in, not discovered in production.

▶️ YouTube (Data API v3)

  • 10,000 quota units/day; each upload = 1,600 → ~6 uploads/day per project.
  • Separate ~100 search.list calls/day bucket.
  • Per-channel ~10 uploads/24h regardless of quota.
  • No Shorts flag — vertical ≤60s is auto-classified; add #Shorts.
  • OAuth youtube.upload + verified project; audit ≈ 2–4 weeks for public posting.

📸 Instagram (Graph API)

  • Business account required (Creator not supported for publishing).
  • ~25–100 API posts/24h (sources vary) — aim 1–3 quality Reels/day.
  • Reels 9:16, ~5–90s to land in the Reels tab.
  • 3-step flow: create container → poll status → publish.
  • Scopes: instagram_business_content_publish (old scopes deprecated Jan 2025).
Compliance built into the profile: made_for_kids (COPPA — disables personalized ads/comments for kids content), ai_disclosure (platforms require flagging synthetic/altered media), clean music licensing (Stable Audio over Suno/Udio for commercial safety), and honest commentary/fair-use for TV takes (no re-uploading copyrighted clips). Mass-automation also risks platform "authenticity/spam" enforcement — the human review gate and modest daily caps are the mitigation.
How we build it

Phased roadmap

Ship a thin end-to-end slice first (bikes, footage mode, manual upload), then widen. Each phase is independently useful.

PHASE 0 · Foundations

Profile schema, connectors, state store

ContentProfile model + validation, rclone ingest, media registry (SQLite), secrets, and a Prefect skeleton. Nothing publishes yet.

PHASE 1 · Footage MVP (bikes)

Ingest → scene detect → Whisper → highlight → cut → reframe → caption → LUT → draft → notify

End-to-end for real footage, ending in a Telegram approval + manual upload. Proves the core loop cheaply with mostly OSS.

PHASE 2 · Auto-publish + research

YouTube & IG APIs, scheduling, trend module

Wire official upload APIs with quota-aware scheduling; add trend research + Claude ideation feeding hooks/titles. Approval gate stays.

PHASE 3 · Generative mode (kids)

Script → TTS → music → animation → assemble

Add the generative source strategy and kids profile with COPPA + disclosure + mandatory review. Same publish path.

PHASE 4 · Hybrid mode (TV talk) + learning

Mixed real/generative + analytics feedback loop

Timely episode-drop workflow; pull analytics, attribute wins, auto-tune profile defaults, A/B thumbnails and hooks.

PHASE 5 · Scale

Multi-channel, multi-account, cost & safety hardening

Postgres, multiple channels per niche, budget guardrails, richer policy engine, dashboards.
