Deep dive · component research (2026-sourced)

Use AI where it earns its place.

The core question answered: of ~40 atomic tasks in ReelForge, only 5 genuinely need an LLM. Everything else is deterministic OSS or classical signal processing — cheaper, faster, testable, and reproducible. Here's the map, the task graph, the providers, the learning loop, and how it runs locally first.

Question 1 · where does Claude / an external LLM get used?

The LLM-usage map

Principle: reserve LLMs for language, reasoning, and multimodal judgment. Anything with a deterministic definition (does this frame have motion? where's the loudness peak? what are the word timings?) is OSS/classical. Claude has zero native media generation — it never produces video, images, audio, or voice; it writes the words and the prompts, judges, and orchestrates.

🧠

LLM earns its place — only 5 spots

  • Ideation — synthesize trends + audience + brand voice into hooks, titles, descriptions (Stage 2, optional)
  • Scripting — nursery-rhyme lyrics, TV-take script, scene/shot list (generative mode)
  • Prompt-writing — turn a scene into a strong Veo/Kling/Flux prompt
  • Multimodal judgment — brand-fit / safety scoring of frames (policy nuance)
  • Synthesis of feedback — theme up comment sentiment & propose new hook variants from winners (Stage 7)
⚙️

Deterministic / OSS — everything else

  • Ingest, dedupe, probe, transcode — rclone / ffprobe / hashlib
  • Scene cuts, transcription, word timings — PySceneDetect / WhisperX
  • Interest signals — librosa, OpenCV, telemetry, YOLO/MediaPipe
  • Highlight fusion — scipy peak-finding + soft-NMS (no model)
  • Cut, reframe, captions, color grade, mux — MoviePy / FFmpeg
  • Upload, analytics, bandit choice, scorer, attribution — APIs / MABWiser / XGBoost / SHAP

Question (interjection) · one task = one thing

Atomic, single-responsibility task DAG

Every stage decomposes into small ops that each do exactly one thing — individually testable, swappable, and cacheable. In Prefect these are @tasks composed into @flows; the ContentProfile decides which ops run and with which adapter. Swap op_transcribe_whisperx for op_transcribe_api without touching anything downstream.

Question 5 · multiple sources to find interesting clips

Multi-signal highlight detection

No single signal is reliable, and none needs an LLM. ReelForge computes several independent, cheap signals over the timeline, normalizes each, and fuses them into one ranked highlight list. This is classic signal processing — reproducible and tunable per niche.

The signal catalog (each = one op)

SignalOSS tool / methodCatchesGTX 1060
Shot / scene changePySceneDetect (Content + Adaptive)cuts, new scenery, paceCPU ✓

Speech salienceWhisperX + KeyBERT / TF-IDFpunchlines, key phrases~1–1.5 GB ✓

📟 Action-cam telemetrytelemetry-parser · exiftoolg-force spikes, speed, GPS, altitude, jumpsCPU ✓ (one pass)
Insta360 telemetry is the killer signal for bike POV. Insta360 .insv/.mp4 embed gyroscope, accelerometer, GPS, altitude, speed and bearing. It's extractable without video decoding via telemetry-parser (the Rust lib behind Gyroflow, has Python bindings) or exiftool. A simple threshold on accelerometer/g-force magnitude flags jumps, hard braking, and near-misses in one cheap pass — no ML, no LLM. This is exactly the kind of classical approach that beats "ask a vision model what's interesting."

Fusion — classical, no model

STEP 1

Normalize

Each signal → 0–1 over the timeline (z-score or min-max per clip).

STEP 2

Weight & sum

Weighted linear combination; weights come from the ContentProfile (bikes lean on telemetry+motion).

STEP 3

Peak-find

scipy.signal.find_peaks on the fused score → candidate moments.

STEP 4

Soft-NMS

Temporal non-max suppression dedupes overlapping peaks → final ranked segments.

When is a vision LLM worth adding on top? Only for semantic questions the signals can't answer — "is this the funny part of the story?", multi-clip narrative coherence, or brand/safety judgment. It ranks the shortlist; it doesn't scan the whole video.

Question 2 · generative snippet providers & can Claude do it

Generative media: providers + Claude's real role

Short answer: Claude cannot generate video, images, audio, or voice — confirmed by Anthropic docs (text + vision-input + tool-use only). Claude is the writer & orchestrator: it drafts scripts, writes the prompts, judges the results, and calls the generators via tool-use/MCP. The pixels/audio come from specialist models, best reached through an aggregator so each stays one swappable model_id.

🧭 Aggregator-first

fal.ai (cheapest video, no cold-start) or Replicate (widest catalog) expose Veo/Kling/Runway/Flux/etc. behind one API. One op_generate_media(model_id, prompt) task; start cheap, upgrade hero shots by changing a string.

GTX 1060 reality: good for scripting (Claude, remote) and local TTS (Kokoro/Piper). Production video & music generation need cloud (32 GB+ VRAM); the 1060 can only prototype tiny quantized clips slowly. So the generative layer is cloud APIs via fal.ai, while the footage pipeline runs fully local.
Follow-up · MCP servers for the generative layer

The MCP layer

MCP (Anthropic's open Model Context Protocol) is how Claude reaches the generators as tools — search a model, check its schema, run it, get the file back — without a bespoke integration per provider. In 2026 nearly every media provider ships one. ReelForge uses MCP for the agentic work and direct SDK/API calls for the deterministic work; both hit the same providers.

Two ways in, on purpose. MCP (agentic): Claude plans a shot list, writes prompts, calls a generator, looks at the result, and re-rolls — interactive, in the ideation/generative-build loop and the review console. Direct API via a thin adapter (deterministic): the Prefect op_gen_* tasks call the provider SDK for reproducible, retryable, cacheable batch runs. Same provider (e.g. fal), two entry points — so a run is repeatable but Claude can still improvise.

Question 3 · how the learning loop improves the next generation

The learning loop

Views improve because the system logs what it shipped, measures what happened, and biases the next run — using classical ML, not "ask an LLM if it'll go viral." Two complementary mechanisms: a bandit that keeps picking better hooks over time, and a pre-publish scorer that ranks candidate variants before they're posted.

1 · What to log

Per post: hook_type, caption_style, length_s, music_mood, lut, topic + outcomes views, avg_view_duration, retention_curve[], swipe_away, likes/comments/shares. The first-3-second retention is the single most predictive signal.

2 · Bandit (online)

MABWiser Thompson sampling over hook archetypes (text-overlay, hard-cut, music-drop, pattern-break, surprise). Reward = early retention / watch-time. ~70/30 exploit/explore. It converges toward the hooks your audience actually rewards.

3 · Scorer (offline)

XGBoost trained on logged features predicts engagement; SHAP explains why a variant ranks high, surfaced at the review gate. Trains in <1 min on the 1060. Ranks candidates before posting so you publish the best of N.

LLM vs classical split here: bandit selection, scoring, retention analysis, and sentiment classification are all classical/OSS. Claude is used only for open-ended synthesis — turning "these 200 comments + these winning features" into new hook ideas and a weekly theme summary. That closes the loop with fresh creative, fed by hard numbers.
Question 4 · tech stack & how it runs

Tech stack

Python core, Prefect 3 for orchestration (plain Python functions become tasks/flows — trivial to test locally, one env var to run in cloud). Storage, state, and secrets are abstracted so the same code runs on your laptop and in the cloud.

Orchestration

Prefect 3 — native Python, runtime branching (matches dynamic clip selection), retries/scheduling/observability, no per-task fees. Dagster is the alternative if asset-lineage matters.

Media & ML

FFmpeg + MoviePy 2, PySceneDetect, faster-whisper/WhisperX, OpenCV, librosa, MediaPipe, YOLOv8, telemetry-parser.

Storage abstraction

fsspec — local FS ↔ S3/GCS behind one interface. Zero code change from laptop to cloud bucket.

Config & secrets

pydantic-settings — the ContentProfile + env vars; SecretStr for keys, never logged.

State DB

SQLite → Postgres via one connection string (SQLAlchemy). Content ledger + job state + metrics.

Review gate

FastAPI webhook + Telegram/Slack bot; Prefect waits on the approval signal (24h timeout → auto-reject).

Publish

google-api-python-client (YouTube Data + Analytics), Meta Graph API for IG. Quota-guarded.

Learn

MABWiser, XGBoost, SHAP, VADER/DistilBERT, pandas/scipy; optional Feast feature store + MLflow.

AI

anthropic SDK for Claude (ideation/scripting/prompts/judgment); fal.ai for generative media; Kokoro local TTS.

GTX 1060 6GB verdict: viable baseline for the footage pipeline. faster-whisper small/medium + INT8 runs in ~1–1.5 GB; scene detect + audio + optical flow on CPU; MediaPipe/YOLO on keyframes. Estimated ~1 video / 3 min in batch, ~50–100/day. The real bottlenecks are API quotas and your approval time, not the GPU. Generative video/music offloads to cloud regardless.
Local first → cloud → docker

How it's run

Start on your Linux box, no cloud account required. Because storage/state/config are abstracted, promoting to cloud is an env change, and containerizing is a Dockerfile — not a rewrite.

TIER 1 · LOCAL (start here)

One machine, zero cloud

Prefect OSS server on localhost, media on local FS (fsspec local), state in SQLite, secrets in .env, GPU used directly. Run a flow with python -m reelforge run --profile bike_pov.

TIER 2 · DOCKER

Reproducible container + GPU

Base image nvidia/cuda:12.3-runtime + ffmpeg; docker compose with worker + Postgres + FastAPI (+ optional Redis). --gpus all via nvidia-container-toolkit. Same code, pinned deps.

TIER 3 · CLOUD

Portable, no rewrite

Flip env: STORAGE=s3://…, DATABASE_URL=postgres://…, point Prefect worker at a cloud work-pool. Long/GPU jobs on a cloud GPU VM; short tasks fit Cloud-Run-style serverless containers (mind the timeout on GPU jobs).
